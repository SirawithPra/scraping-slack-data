# คู่มือเดโม — ทำอะไรบ้าง ตามลำดับ

เอกสารนี้คือสิ่งที่ต้องทำจริงในวันเดโม เรียงตามเวลาที่ทำ ไม่ใช่ตามความสำคัญของฟีเจอร์
ตัวเลข beat ตรงกับ `/meowtam demo` ในโค้ด ([slack-bot/src/app.ts](../slack-bot/src/app.ts))
ถ้าเอกสารนี้กับโค้ดไม่ตรงกัน **โค้ดถูก** — พิมพ์ `/mt demo` แล้วอ่านจากหน้าจอ

ค่าที่ตั้งไว้อยู่ตอนนี้ (จาก `.env` ทั้งสองฝั่ง):

| ของ | ค่า |
| --- | --- |
| ช่องที่บอทโพสต์ | `#test-meow` (`DIGEST_CHANNEL`) — `DAILY_CHANNEL` ว่าง จึงใช้ช่องเดียวกัน |
| คนที่ได้ standup DM | `STANDUP_USERS` 2 คน |
| งานตามเวลา | **ปิดอยู่** (`ENABLE_SCHEDULE` ว่าง) — ทุกอย่างยิงด้วยมือผ่าน `/mt demo` |
| ข้อมูลงาน | จาก pipeline `http://127.0.0.1:8899` (`TAM_API_URL`) ไม่ใช่ fixture ของบอท |
| เขียนลง YouTrack | **เปิด** ฝั่ง pipeline (`YOUTRACK_WRITE=1`) → บอทเขียนคอมเมนต์จริงผ่าน pipeline |
| เกณฑ์งานเงียบ | 5 วันทำการ (`TAM_STALE_WORKDAYS`) |
| เกณฑ์เรื่องค้างซ้ำ | 3 เช้า (`TAM_DAILY_PENDING_DAYS` default) |

### ล้างของเก่าทิ้งก่อน — ทำเป็นอย่างแรก

รอบซ้อมทิ้งของไว้สี่ที่: ประวัติ daily, บันทึกว่า "เคยประกาศไปแล้ว", decision ที่กดเก็บไว้ และ corpus

**สำรองก่อนเสมอ** — ไฟล์พวกนี้เป็นของจริงของทีม (คำตอบ daily ที่คนพิมพ์เอง) ลบแล้วไม่มีใครสร้างคืนให้

```bash

mkdir -p .demo-snapshot
cp slack-bot/data/dailies.json slack-bot/data/announcements.json \
   slack-bot/data/decisions.json .demo-snapshot/ 2>/dev/null

```

```bash
printf '[]\n' > slack-bot/data/dailies.json        # ประวัติ daily ทุกวัน → beat 1 เริ่มจากศูนย์ beat 3 โพสต์ใหม่ได้

/mt demo reset      ตัวนับ beat กลับไป 1 (ตัวนับอยู่ในหน่วยความจำ restart บอทก็รีเซ็ตเหมือนกัน)
```

**ถ้าอยากเก็บ daily ของจริงไว้** ลบเฉพาะของวันนี้ก็พอ แค่นี้ beat 1 กับ beat 3 ก็ทำงานได้แล้ว:

```bash

p = pathlib.Path('slack-bot/data/dailies.json')
today = datetime.date.today().isoformat()
rows = json.loads(p.read_text(encoding='utf-8'))
kept = [r for r in rows if r.get('date') != today]
p.write_text(json.dumps(kept, ensure_ascii=False, indent=2), encoding='utf-8')
print(f'{len(rows)} วัน → เหลือ {len(kept)}')
PY
```

### เซิร์ฟเวอร์สองตัว — ปกติรันอยู่แล้ว

เครื่องนี้ลง `deploy/install.sh` ไว้ **dashboard กับบอทจึงขึ้นเองตั้งแต่ login และ launchd เปิดใหม่ให้ถ้าตาย**
ไม่ต้องเปิดเทอร์มินัลค้างไว้เลย เช็กด้วย `./demo.sh` หรือ `launchctl list | grep com.tam`

ถ้าจะรันมือ (เครื่องอื่น หรือปิด launchd ไว้):

```bash
# เทอร์มินัล 1 — pipeline (ต้องขึ้นก่อน บอทอ่านจากตัวนี้)
cd pipeline
python3 -m tam.web.server --records data/processed/real_all.json --days 7 --port 8899
```

รอจนขึ้น `INFO Ready: … record(s), … topic(s), … blocked` แล้วค่อยเปิดบอท
ถ้าเปลี่ยน corpus ให้ชี้ `--records` ไปไฟล์ที่เพิ่ง build (ตัวที่มี embedding cache คู่กันจะขึ้นเร็ว ไม่ต้อง embed ใหม่)

`--days` คือหน้าต่างของ digest ไม่ใช่ขนาด corpus — **7 คือค่าที่ควรใช้กับข้อมูลจริง** เพราะ digest แปลว่า
"อะไรขยับบ้างสัปดาห์นี้" ค้นหายังเจอทั้ง corpus อยู่ดี (`real_all.json` มีข้อความตั้งแต่ 8 มิ.ย. ถึงเมื่อวาน
อยู่ในเจ็ดวันหลังสุด 43 ข้อความ) เลข `--days 3650` ที่เห็นใน `pipeline/README.md` มีไว้สำหรับ
`sample_combined.json` ซึ่งวันที่เก่ามาก ถ้าไม่เปิดหน้าต่างให้กว้างจะไม่เหลืออะไรใน digest เลย

**เช็กก่อนว่ามีตัวที่รันอยู่แล้วหรือยัง** — เปิดซ้ำจะได้ `Address already in use` เฉย ๆ ไม่ได้พัง:

```bash
curl -s 127.0.0.1:8899/api/health     # ตอบมา = มีตัวรันอยู่แล้ว ใช้ตัวนั้นได้เลย
```

ดูสามค่าในคำตอบ: `records_path` ต้องเป็น corpus ที่ตั้งใจ, `window_days` คือ `--days` ที่ตัวนั้นเปิดไว้,
`built_at` คือเวลาที่ index ถูกสร้าง ถ้าสามอันนี้ถูกก็ไม่ต้องรีสตาร์ท

```bash
# เทอร์มินัล 2 — บอท
cd slack-bot
npm start
```

ต้องเห็นบรรทัดสรุปตอนบูต ที่บอกจำนวน work item + จำนวนข้อความ + ว่าอ่านจาก **pipeline** ไม่ใช่ fixture
ถ้าขึ้นว่า fixture แปลว่า `TAM_API_URL` ไม่ติด — หยุดแล้วแก้ก่อน อย่าเดโมทับ

### ทีละ beat

#### beat 1 · ก่อนเริ่ม — เขียนประวัติ daily ย้อนหลัง

**ของจริงคือ** ไม่มี — ของจริงคือเช้าที่ผ่านไปเองจริง ๆ นี่คือ beat เดียวที่ปั้นข้อมูล
**ลงที่ไหน** ไฟล์ `slack-bot/data/dailies.json` ไม่ได้โพสต์อะไรลง Slack

**ตัวอย่างที่จะเห็น** (ตอบกลับเฉพาะคนพิมพ์)

```text
▶ beat 1 — เขียนประวัติ daily 2 เช้าไว้แล้ว (2026-08-18, 2026-08-19)
ทุกเช้ามีบรรทัดเดิมจาก @เก่ง ธ. ว่ารอ requirement หน้า redemption จาก PO
เขียนคนละแบบทุกวัน เพื่อให้เห็นว่าตัวนับจับได้ว่าเป็นเรื่องเดียวกัน
⚠️ ข้อมูลจำลอง ติดป้ายไว้ทุกที่ที่แสดง · ลบด้วย `/meowtam demo clear`

**ระวัง** ถ้าไม่ได้ตั้ง `STANDUP_USERS` จะไม่ทำอะไรเลยแล้วบอกให้ไปตั้งก่อน

**พูดออกไปตรง ๆ ว่าอันนี้จำลอง** ดีกว่าให้เขาถาม

## 4. คำสั่งเดโม

```
/mt demo          ดูว่า beat ถัดไปคืออะไร + ทั้ง 11 beat ตรงกับคำสั่งจริงตัวไหน

## 5. ลิงก์ที่ใช้ตอนนำเสนอ

**URL สาธารณะ** — `./demo.sh share` คืนลิงก์ `https://<สุ่ม>.trycloudflare.com` ที่ชี้มาที่ dashboard ของเครื่องนี้
ส่งให้คนในห้องเปิดเองได้ระหว่างที่เราพูด ไม่ต้องต่อจอ ลิงก์เปลี่ยนทุกครั้งที่เปิดใหม่ และ **ไม่มีรหัสผ่านกั้นฝั่งอ่าน**
(route ที่เขียนข้อมูลยังต้องใช้ `X-TAM-Token` เหมือนเดิม) ในนั้นมีข้อความ Slack จริง ถ้าไม่อยากให้ชื่อจริงขึ้นจอ
ตั้ง `TAM_NAMES=pseudonym` ทั้ง `pipeline/.env` และ `slack-bot/.env` แล้ว `./demo.sh restart` · จบแล้วปิดด้วย `./demo.sh unshare`

## 6. จบเดโมแล้ว

```bash
./demo.sh unshare    # ปิด URL สาธารณะ — ทำก่อนอย่างอื่น ลิงก์ยังเปิดอยู่คือคนยังเข้าได้
./demo.sh restore    # เอาข้อมูลก่อน reset กลับมา (daily ของจริง, decision, corpus) แล้ว build index ใหม่ให้
```
```
/mt demo clear     ลบข้อมูลจำลองทั้งหมด บอกจำนวนเช้าและจำนวนคำตอบที่ลบ
```

ทำทันทีหลังจบ ไม่ต้องรอ — ข้อมูลจำลองที่ค้างไว้ข้ามวันคือข้อมูลจำลองที่จะกลายเป็นข้อมูลจริงโดยไม่มีใครตั้งใจ
ส่วนคอมเมนต์ที่เขียนลง YouTrack ตอน beat 8/9 **เป็นของจริงและลบไม่ได้จากตรงนี้** ถ้าไม่อยากให้ค้าง ไปลบใน YouTrack เอง

## 7. พังตรงไหน ทำยังไง

| อาการ | เพราะ | ทำ |
| --- | --- | --- |
| บอทบูตแล้วบอกว่าอ่านจาก fixture | `TAM_API_URL` ไม่ติด หรือ pipeline ยังไม่ขึ้น | เปิด pipeline ก่อน แล้ว restart บอท |
| `Address already in use` ตอนเปิด pipeline | มี `tam.web.server` รันอยู่แล้วที่ port นั้น | `curl -s 127.0.0.1:8899/api/health` ดูว่าโหลด corpus ถูกไหม ถูกก็ใช้ตัวเดิม · จะเปลี่ยนค่าค่อย `lsof -nP -iTCP:8899 -sTCP:LISTEN` เอา PID ไป `kill` แล้วเปิดใหม่ |
| บอทไม่ยอมบูต บอกว่าอ่าน pipeline ไม่ได้ | ตั้งใจให้เป็นแบบนั้น — ถ้าบูตต่อจะเสิร์ฟข้อมูลเก่าที่หน้าตาเหมือนของสด | เช็กว่า `python3 -m tam.web.server` ยังรันอยู่ที่ port 8899 |
| beat 3 บอกว่าโพสต์ไปแล้ว | ซ้อมไปแล้ววันนี้ | `/mt daily post again` |
| beat 6 บอกว่าไม่มีงานเงียบพอ | ไม่มีจริง ๆ และมันไม่ปั้น | พูดออกไปว่านี่คือพฤติกรรมที่ถูก แล้วอ่านตัวที่เงียบที่สุดที่มันบอกมา |
| beat 8 ค้างนาน | กำลัง embed + cluster ใหม่ทั้ง corpus | รอ มันจะตอบเป็นผลลัพธ์ตอนเสร็จ อย่ากดซ้ำ |
| beat 9 บอกว่าไม่มี drift | ไม่มีเรื่องที่ Slack กับ ticket ไม่ตรงกันจริง ๆ | ข้ามไป beat 10 หรือใช้ `/mt silent` โชว์ ticket ที่เงียบแทน |
| ข้อมูลใน Slack ไม่ตรงกับ dashboard | บอท cache ไว้ตั้งแต่บูต | `/mt reload` (ไม่ต้อง restart) |
| ชื่อคนขึ้นเป็น `U0…` | ยังไม่ได้ดึงชื่อ | `python3 -m tam.ingest.users --fetch` แล้ว `/mt reload` |

**อัดวิดีโอสำรองไว้** เดโม Slack สดพังได้ทุกทาง — wifi งาน, rate limit, workspace เด้ง login
วิดีโอที่เล่นได้มีค่ามากกว่าเดโมสดที่ไม่ขึ้น
